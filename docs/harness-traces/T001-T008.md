## Brainstorm

These tasks are setup-only and should not introduce feature business logic. The useful test target is a setup contract that proves required files exist, Python skeleton files compile, package metadata contains expected dependencies/scripts, env examples do not contain committed secrets, docs include verification commands, and `.gitignore` covers generated artifacts.

Possible approaches:

- Create files directly and verify manually.
- Write a shell-based smoke script.
- Write a pytest setup contract that can later run with the rest of the backend tests.

Chosen approach: write a pytest-compatible setup contract first, then run it through pytest when available and through a dependency-free Python invocation in the current environment.
