## Brainstorm

These tasks form the blocking foundation for later user stories. The safest approach is to add thin infrastructure with no feature business logic: health/errors, domain enums, common schemas, SQLite transaction helpers, local header-based auth helpers, a typed frontend API client, shared UI state components, and structured logging utilities.

Possible approaches:

- Implement a broad framework upfront with all future routes.
- Keep this phase limited to infrastructure and contracts needed by later tasks.
- Add real auth or real LLM configuration now.

Chosen approach: keep the foundation small and deterministic. Do not add real LLM clients, production auth providers, FAQ business logic, source management, or chat behavior in this phase.
